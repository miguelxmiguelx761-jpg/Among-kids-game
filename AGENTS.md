# Among Kids — developer notes (Base44 dev environment)

Native Android app (Kotlin + Jetpack Compose, single `:app` module). The Base44
environment runs it in Docker; see `docker-compose.base44.yml`.

    docker compose -f docker-compose.base44.yml up -d --build   # start (first run ~10 min)
    docker compose -f docker-compose.base44.yml logs -f android # build + render output
    docker compose -f docker-compose.base44.yml exec android gradle :app:assembleDebug

## Why the preview is rendered screenshots

An Android app cannot run in a browser and this sandbox has no `/dev/kvm`, so an
emulator is not possible. Instead the preview shows the app's **real Compose UI**,
rendered headlessly with the Robolectric + Roborazzi setup the repository already had
(`app/src/test/screenshots/greeting.png` came from the same tooling):

- `app/src/test/java/com/example/preview/PreviewCaptureTest.kt` composes the real
  `AmongKidsRootApp` and taps the same controls a player taps, writing one PNG per
  screen to `$PREVIEW_OUT_DIR` (the `preview-out` volume).
- `.base44/preview/run.sh` builds the APK, runs that test, writes `manifest.json` for
  the page's status pill, and then **watches `app/src` — any edit re-renders the
  screens automatically** (about 40 s per cycle).
- `.base44/preview/index.html` is the gallery served by nginx on port 3000.

To add a screen: add a test to `PreviewCaptureTest` writing `<id>.png`, then add the
matching id to the `SCREENS` list in `index.html`.

## Non-obvious findings

- `debug.keystore` is required by the debug signing config but is gitignored and
  normally generated by Android Studio. `run.sh` creates the standard one
  (store/key password `android`, alias `androiddebugkey`) when it is missing.
- Release builds additionally need `KEYSTORE_PATH`, `STORE_PASSWORD`, `KEY_PASSWORD`
  and the upload keystore; the dev environment only builds debug, so they are not set.
- The app needs **no external credentials**. `GEMINI_API_KEY` is only a commented-out
  line in `.env.example` (read by the `secrets` Gradle plugin) and no source file
  references it or `BuildConfig`; `firebase-ai` is a declared but unused dependency.
  `googleServices.missing.passthrough=true` means no `google-services.json` is needed.
- Ignore the KSP stack trace about `ApplicationManager.getApplication()` returning
  null — harmless KSP/AWT noise in a container (`JAVA_TOOL_OPTIONS` sets headless).
- Robolectric downloads its `android-all` jar for API 36 on the first test run, and the
  Gradle cache lives in the `gradle-home` volume; do not `down -v` it needlessly.
- The Android SDK/Gradle live in the image (`android-toolchain.Dockerfile`); only the
  toolchain is baked in, the repository is bind-mounted, so edits need no rebuild.
- Rendering is done with `--rerun-tasks` because Gradle would otherwise consider the
  screenshot test up to date and skip re-capturing.
